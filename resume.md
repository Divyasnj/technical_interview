# about google auth
Google OAuth 2.0 is a secure authentication and authorization protocol that allows users to log in to your application using their Google account — without sharing their password with your app.

🎯 Why We Use Google OAuth?

In your CablePay and other MERN apps, it helps:

✅ Avoid storing passwords

✅ Provide secure login

✅ Quick user onboarding

✅ Trusted authentication system


🧠 What is OAuth 2.0?

OAuth 2.0 is an authorization framework.

It allows:

A user

To give permission

To an application

To access limited data

Without sharing credentials

🔄 How Google OAuth 2.0 Works (Step-by-Step)

Let’s say a user clicks “Login with Google”:

Step 1️⃣ User Clicks Login

Your frontend redirects user to Google login page.

Step 2️⃣ User Authenticates

Google asks:

Email

Password

Step 3️⃣ Google Sends Authorization Code

After success, Google sends back an authorization code to your backend.

Step 4️⃣ Backend Exchanges Code for Token

Your backend sends the code to Google → Google returns:

Access Token

ID Token (JWT)

Step 5️⃣ Verify Token

Backend verifies token using Google public keys.

Step 6️⃣ Create Your Own JWT

After verification:

You create your own JWT

Send it to frontend

User is logged in


🔑 Difference Between OAuth & JWT
OAuth 2.0	JWT
Authorization protocol	Token format
Used for login with Google	Used for session management
External provider	Generated by your backend

Google OAuth 2.0 is an authorization protocol that allows users to log into an application using their Google account without sharing their password. It works using an authorization code flow where Google authenticates the user, returns a token, and the backend verifies it before creating its own JWT for session management.


# json web token
JWT (JSON Web Token) is a compact, secure way to transmit information between two parties as a JSON object.

It is mainly used for:

✅ Authentication

✅ Authorization

✅ Secure data transfer

🧠 Simple Definition (Interview Ready)

JWT is a token-based authentication mechanism where the server generates a signed token after login, and the client sends that token with every request to access protected resources.

🧱 Structure of JWT

A JWT has 3 parts separated by dots:

xxxxx.yyyyy.zzzzz
1️⃣ Header

Contains:

Algorithm (HS256, RS256)

Token type (JWT)

Example:

{
  "alg": "HS256",
  "typ": "JWT"
}
2️⃣ Payload

Contains user data (claims):

{
  "userId": "123",
  "role": "admin",
  "exp": 1712345678
}

⚠️ Payload is encoded, NOT encrypted.

3️⃣ Signature

Created using:

HMACSHA256(
  base64UrlEncode(header) + "." +
  base64UrlEncode(payload),
  secret_key
)

This ensures:

Token is not tampered

Token is valid

🔄 How JWT Works (Step-by-Step)
Step 1️⃣ User Logs In

User sends email & password.

Step 2️⃣ Server Validates

If correct → server generates JWT.

Step 3️⃣ Token Sent to Client

Client stores token (usually localStorage or cookie).

Step 4️⃣ Client Sends Token

In every request:

Authorization: Bearer <token>
Step 5️⃣ Server Verifies

Server checks:

Signature

Expiration time

If valid → access granted.
